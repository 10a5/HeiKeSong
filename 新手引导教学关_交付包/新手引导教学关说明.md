# 神经断层 · 新手教学关（神经校准）设计与接入说明

> 版本：v1.0 · 适用项目：`HeiKeSong-main` · 引擎：Godot 4.x（Compatibility）
> 相关文件：`tutorial.tscn`、`tutorial.gd`、`project.godot`

---

## 1. 教学目标

新手教学关只解决一件事：**让玩家在 2～4 分钟内，亲手做出这款游戏最核心的四类操作，并且每一步都成功一次。**

这款游戏的学习成本集中在三处：

| 难点 | 玩家的困惑 | 教学关的处理 |
| --- | --- | --- |
| 操作逻辑是「卡牌驱动动作」 | 以为要记连招，不知道动作从手牌来 | 第 3 步强行让玩家打出一张牌，并展示能量消耗 |
| 战斗是「读抬手 → 闪避 → 反击」 | 站着对拼，被打死也不知道怎么躲 | 第 4 步教学关给敌人 3 秒缓冲，再用专用手牌只给【翻滚】 |
| 位移牌是生存手段而非伤害牌 | 把翻滚当输出用 | 用「只给一张翻滚」的手牌强制练习翻滚 |

设计原则：

1. **一次只教一个动词**，不叠加新概念。
2. **每一步都有可验证的成功条件**，玩家做对了提示才推进。
3. **教学手牌由关卡直接控制**，不靠随机抽牌碰运气。
4. **随时可以退出**，右上角常驻「跳过教学」按钮。

## 2. 入口与跳转

- `project.godot` 的 `run/main_scene` 指向 `res://tutorial.tscn`，因此 **F5 默认先进入教学关**。
- 教学完成后，右上角按钮变为「进入第一层 →」，调用：

  ```gdscript
  get_tree().change_scene_to_file("res://floor_one.tscn")
  ```

- 玩家随时可以点「跳过教学，进入第一层」，跳到同一个场景。
- 按 `R` 重置教学关：`get_tree().reload_current_scene()`。
- 想关闭教学（例如做交付演示直接进第一层），把 `project.godot` 里 `run/main_scene` 改回 `res://floor_one.tscn` 即可，教学关本身不受影响，仍可用 F6 单独运行。

## 3. 关卡空间布局

教学关复用 `main.gd` 的灰盒训练场几何体，再沿 Z 轴正向铺一条单线路线，玩家只会朝一个方向推进，不需要找路。

| 位置（世界坐标） | 内容 | 作用 |
| --- | --- | --- |
| `Player (0, 0, 6)` | 出生点 | 起点 |
| `MovePad / 青色圆环 (0, 0, 1)` | 移动训练区 | 第 1 步目标点 |
| `JumpBarrier (0, 0.36, -1.8)` | 高 0.72 米的低墙 | 第 2 步必须跳过去 |
| `JumpPad / 橙色圆环 (0, 0, -3)` | 落地确认点 | 第 2 步完成判定 |
| `CombatPad (0, 0.04, -5.4)` | 战斗练习区 | 第 4～5 步 |
| `TutorialBoxer (0, 0, -6)` | 教学敌人：街道拳击手（`enemy_variant.gd` 的 `boxer` 变体） | 初始隐藏，第 4 步才出现 |

同时包含三块 `Label3D` 世界内提示牌：

- `移动训练 / WASD / 方向键`
- `跳过低墙 / 空格`
- `读抬手 → 翻滚 → 反击`

> 低墙高度 0.72 米大于角色可自动跨越的 0.30 米台阶阈值，但低于约 1.3 米的跳跃高度，因此**必须跳跃**才能通过，用来验证跳跃。

## 4. 五个教学步骤（核心）

`tutorial.gd` 中的 `step` 变量驱动整个流程，`_show_step(n)` 推进阶段，`_physics_process` 检测成功条件。

| step | 显示进度 | 提示文案 | 成功条件 | 手牌 |
| --- | --- | --- | --- | --- |
| 0 | 1 / 5 | 先熟悉移动：走到青色圆环。WASD / 方向键移动，鼠标拖动旋转视角。 | 平面距离 `< 1.8` 米 | 正常随机 4 张 |
| 1 | 2 / 5 | 很好。越过低墙练习跳跃。走到橙色圆环，按空格起跳。 | 玩家 `y > 0.55`（或到达圆环且 `y > 0.25`）**且** `z < -3.2` | 正常随机 4 张 |
| 2 | 3 / 5 | 动作由手牌驱动。按 1–4 或点击任意一张手牌，观察能量消耗。 | 任意一张牌打出成功（`action_played`） | 正常随机 4 张 |
| 3 | 4 / 5 | 最后是战斗节奏。敌人将在 3 秒后开始攻击。靠近敌人，等它抬手出现红色预警，在落刀前打出【翻滚】躲开。 | 在预警期间成功翻滚（`roll`） | **只有 1 张【翻滚】**，其余槽位留空且不补牌 |
| 4 | 5 / 5 | 闪避成功。趁敌人收招反击。手牌已换成攻击动作，打出【出拳】击败它。 | 敌人 `is_dead` | **3 张【出拳】+ 1 张【翻滚】**，并恢复 1 秒补牌规则 |
| 5 | 完成 | 校准完成。你已经掌握移动、跳跃、出牌和闪避。点击右上角进入第一层。 | 玩家点击按钮 | 与第 4 步相同，保持 1 秒补牌规则 |

### 详细的成功判定（`_physics_process`）

```gdscript
match step:
    0:
        if flat_position.distance_to(Vector2(beacon_position.x, beacon_position.z)) < 1.8: _show_step(1)
    1:
        if player.global_position.y > 0.55 or (flat_position.distance_to(...) < 1.5 and player.global_position.y > 0.25): _jump_seen = true
        if _jump_seen and flat_position.y < -3.2: _show_step(2)
    2:
        if _card_seen: _show_step(3)
    3:
        if _roll_seen: _show_step(4)
    4:
        if is_instance_valid(enemy) and enemy.is_dead: _show_step(5)
```

`_roll_seen` 有两路来源，任一满足即可：

1. `player.action_played` 信号中 `action_name == "roll"`（玩家确实打出了翻滚）；
2. `player.status_changed` 中文本包含「翻滚」——这条覆盖了 `enemy.gd` 在成功闪避时发出的 `翻滚闪避成功 · 等待收招反击`，即**真·闪避成功**。

## 5. 手牌控制机制（本教学关的关键实现）

随机抽牌无法保证第 4 步手里一定有翻滚，因此教学关**直接改写牌堆**。

### 冻结补牌

```gdscript
const FROZEN_REFILL_DELAY := 9999.0
deck.refill_delay = FROZEN_REFILL_DELAY
```

`deck.gd` 的空槽补牌依赖 `refill_delay`，把它推到 9999 秒后，**空槽在教学期间永远不会自动补牌**，玩家不会因为随机补牌而拿到不该出现的动作。

### 指定手牌

```gdscript
const ROLL_LESSON_HAND: Array[String] = ["roll"]
const ATTACK_LESSON_HAND: Array[String] = ["slash", "slash", "slash", "roll"]
```

`_lock_hand(kinds)` 的行为：

1. 把当前手牌、抽牌堆、弃牌堆的**所有实体牌**收进一个 `pool`（保证牌总数不丢不错）；
2. 按 `kinds` 顺序从 `pool` 里取出对应种类的牌放进手牌槽位；
3. 找不到就从 `pool` 之外新建一张（用 `deck._next_card_id` 递增 id）；
4. 空槽位把 `refill_time_left` 设为 `FROZEN_REFILL_DELAY`，**保持为空**；
5. 剩余实体牌全部退回抽牌堆；
6. 顺手把能量补满（`player.energy = player.max_energy`）并发出 `energy_changed`、`piles_changed`，让 HUD 立刻刷新。

> 注意：`_next_card_id` 是 `deck.gd` 的内部变量。GDScript 的下划线只是命名约定，跨脚本访问合法；如果后续把 `deck.gd` 重构为强封装，应改为在 `deck.gd` 中新增 `make_card(kind)` 接口。

### 教学结束恢复

`_show_step(4)` 与 `_show_step(5)` 都会调用 `_restore_deck_rules()`：把 `refill_delay` 还原为 1.0，并把**所有槽位的 `refill_time_left` 清零**。

**为什么恢复必须在第 4 步就发生，而不能只放在第 5 步：**

`_lock_hand()` 会把**每一个**槽位的 `refill_time_left` 都写成 `FROZEN_REFILL_DELAY`（不只是空槽）。原来的实现只在 `_show_step(5)` 恢复，于是整个第 4 步战斗期间：

- `refill_delay` 仍是 9999，打出的牌空出的槽位拿到的计时就是 9999；
- 玩家手里只有 3 张【出拳】+ 1 张【翻滚】，**打掉的空槽永远不会补牌**；
- 一旦三张【出拳】没打完敌人（例如打空、或被击退打断），玩家就再没有攻击手段，卡在第 4 步。

因此恢复点前移到第 4 步——攻击手牌已经是最后一套教学手牌，玩家此时已进入真实战斗，必须按正式规则补牌。第 5 步保留同样的调用作为保险。修好之后：打出一张牌 → 该槽约 1 秒后从抽牌堆补回一张新牌（实测补回的是【护盾】）。

> 验收断言见 `tests/test_tutorial.gd`：「Normal refill returns with the attack hand, not one step later」与「The emptied slot draws a replacement instead of sitting at the frozen delay」。这两条断言会在恢复点被挪回第 5 步时立刻失败。

## 6. 战斗节奏教学的两个特殊处理

### 6.1 敌人延迟 3 秒出手

玩家在第 4 步会先看到一大段文字说明。如果敌人立刻进攻，玩家还在读字就会挨打。

```gdscript
# 进入第 4 步时
_combat_intro_left = 3.0
_show_combat_enemy()   # 敌人现身，但 combat_enabled = false

# _physics_process 中倒计时（不绑定 step，玩家提前翻滚也不会让敌人永远不动）
if _combat_intro_left > 0.0:
    _combat_intro_left = maxf(0.0, _combat_intro_left - delta)
    if _combat_intro_left <= 0.0 and is_instance_valid(enemy):
        enemy.combat_enabled = true
```

`enemy.gd` 的 `combat_enabled == false` 会让 AI 停在 `idle` 状态：不追、不抬手、不落刀，但模型可见，玩家可以先观察它。

倒计时**不绑定在某一个 step 上**：即使玩家在 3 秒内就提前打出翻滚进入第 5 步，计时仍会走完并把敌人放开，避免出现「敌人永远不攻击」的死状态。

提示文案也同步明确写出缓冲时间：**「敌人将在 3 秒后开始攻击。」**

### 6.2 教学敌人是街道拳击手（弱化版）

教学关不再使用 `main.gd` 里那台灰盒假人，而是换成第一层街道遭遇同款的**拳击手**（`enemy_variant.gd` 的 `boxer` 变体，模型 `model/拳击手.glb`）。玩家在教学中练手的目标，就是之后在水岸街区真正会遇到的对手，只是数值被调弱。

在 `_ready()` 中换装并覆盖：

```gdscript
# 继承来的灰盒假人换成拳击手
enemy = ENEMY_VARIANT_SCRIPT.new()
enemy.name = "TutorialBoxer"
enemy.configure_variant(&"boxer")
enemy.boxer_cloak_enabled = false   # 教学对手必须从第一帧就看得见
enemy.spawn_position = enemy_position
enemy.visible = false
add_child(enemy)
enemy.process_mode = Node.PROCESS_MODE_DISABLED
enemy.reset_enemy()
# 弱化必须写在 reset 之后：reset 内部会重跑 _apply_variant_stats()，
# 把街道拳击手的 55 生命与 12 伤害写回来。
_weaken_lesson_enemy()
```

| 参数 | 街道拳击手 | 教学关 | 理由 |
| --- | --- | --- | --- |
| 生命 | 55 | 45 | 3 张【出拳】（各 25 伤害）足够击杀，不用打太久 |
| 伤害 | 12 | 6 | 拳击手攻速快，6 点伤害让新手挨 3～4 下也不会立刻失败 |
| 抬手 | 0.60 秒 | 继承 0.60 秒 | 教学要教的就是街道上真正会出现的那一记出拳，前摇与判定窗口保持一致 |
| 光学隐身 | 首次接近时渐显 | 关闭 | 教学对手要能立刻被读到，不能一边淡入一边逼近 |
| 初始状态 | 可见、待机 | 隐藏、进程禁用 | 前 3 步是纯操作教学，不应该有敌人 |

两个关键实现细节：

1. **入树顺序**：基类 `enemy.gd` 在 `_ready()` 里会设 `PROCESS_MODE_PAUSABLE`，所以 `process_mode` 必须在 `add_child()` **之后**才能改成 `DISABLED`。
2. **数值会被重置**：`enemy_variant.gd` 的 `reset_enemy()` 内部会重跑 `_apply_variant_stats()`，把街道拳击手的生命与伤害写回。因此 `_weaken_lesson_enemy()` 必须在**每次 reset 之后**调用（它同时补写 `max_health`、`health` 和 `attack_damage`），而不是像早期版本那样在 reset 之前调用。开战时的 `_show_combat_enemy()` 同样要这样处理。

另外，教学关覆盖了 `_on_enemy_defeated()`，**不弹出肉鸽奖励面板**，避免打断教学收尾。

`boxer_cloak_enabled` 是 `enemy_variant.gd` 上新增的导出变量，默认 `true`。街道遭遇不设置它，因此第一层拳击手“首次接近时全息渐显”的原行为完全不变。

## 8. 接入步骤（给队友）

1. 把 `tutorial.gd`、`tutorial.tscn` 复制到项目根目录（与 `main.gd` / `player.gd` 同级）。
2. 确认 `main.gd` 中存在教学关依赖的成员：
   - 节点/变量：`player`、`deck`、`enemy`、`hud`、`unlock_terminals`
   - 方法：`_box()`、`_ring()`、`_create_camera()`（由 `super._ready()` 调用）
   - `player.gd` 信号：`action_played(action_name, cost)`、`status_changed(message, is_error)`
   - `enemy.gd`：`spawn_position`、`max_health`、`attack_damage`、`combat_enabled`、`is_dead`、`reset_enemy()`
   - `deck.gd`：`hand`、`draw_pile`、`discard_pile`、`refill_time_left`、`refill_delay`、`piles_changed`、`_next_card_id`
   - 教学敌人依赖街道变体：`enemy_variant.gd`（需含 `boxer` 变体与 `boxer_cloak_enabled`）和 `model/拳击手.glb`。若目标项目没有它们，把 `_use_lesson_enemy()` 整个删掉即可退回基类假人，其余教学逻辑不受影响。
3. 在 `project.godot` 把主场景设为教学关：

   ```ini
   [application]
   run/main_scene="res://tutorial.tscn"
   ```

4. 在 Godot 编辑器中按 F5 验证；单独调试教学关可打开 `tutorial.tscn` 按 F6。
5. 如果项目里没有「第一层」，把 `exit_scene_path`（默认 `res://floor_one.tscn`）换成自己的主关卡路径。

> 移植到别的项目时，最小的必要接口是：一个牌堆对象（可读写手牌）、一个玩家对象（有 `action_played` / `status_changed` 信号和 `energy`）、一个敌人对象（有 `combat_enabled` 开关）。

## 10. 自测清单

- [ ] F5 启动后进入教学关，出生点在青色圆环外侧（能看到圆环在正前方）。
- [ ] 走进青色圆环 → 进度跳到 2 / 5。
- [ ] 不跳跃无法越过低墙；跳过低墙并落到 Z < −3.2 → 进度跳到 3 / 5。
- [ ] 打出任意一张牌（数字键或点击）→ 进度跳到 4 / 5。
- [ ] 进入第 4 步瞬间：出现的是一台**拳击手**（不是灰盒假人）且**站着不动**，身体完全可见、没有全息渐显；手牌只剩一张【翻滚】，其余槽位空着且**不补牌**。
- [ ] 等待 3 秒后拳击手才开始追击和抬手；它用 `box_01` / `box_02` 出拳动画抬拳，而非假人动作。
- [ ] 在抬手预警期间打出翻滚 → 进度跳到 5 / 5，手牌换成 3 张【出拳】+ 1 张【翻滚】，能量满。
- [ ] 打出任意一张【出拳】后，空出的槽位约 1 秒后补回一张新牌（**不能一直是空的**）。
- [ ] 被拳击手打中一次扣 6 点生命（不是街道的 12 点）。
- [ ] 用【出拳】击杀敌人 → 显示「校准完成」，按钮变成「进入第一层 →」。
- [ ] 点击按钮 → 进入第一层水岸街区，牌堆/补牌保持 1 秒规则。
- [ ] 任意时刻点右上角「跳过教学」→ 直接进入第一层。
- [ ] 按 R → 教学关从头开始。

## 11. 已知限制与后续可扩展

**当前限制**

- 教学进度只存在于内存，重启游戏会重新开始教学；本版本没有存档，因此没有做「已教学过就跳过」的判定。
- 第 3 步（出牌教学）不限制具体动作，玩家打出护盾牌也算通过，属于有意放宽。
- 教学关沿用了 `main.gd` 的完整 HUD（卡组浏览、义体按钮、商店入口）。如果希望更纯净，可以在教学期间隐藏这些入口。
- 出牌教学文案只提能量消耗，因为教学期间补牌被冻结，不会展示自动补牌。
- 教学拳击手关闭了光学隐身，因此教学关不教「拳击手会隐身接近」这一条；它属于第一层才出现的威胁信息。
- 第 4 步的完成判定是**打出翻滚**，不是「真的躲开了一刀」。`_show_step(3)` 会把 `_roll_seen` 置回 `false` 并立刻转入第 4 步，所以玩家在进入战斗教学前顺手打出的翻滚不会被计入；但进入第 4 步后只要打出翻滚即通过，不校验是否恰好落在预警窗口内。

**可扩展方向**

1. **存档标记**：教学完成后写一个 `tutorial_completed = true` 到 `user://`，主场景按标记决定是否进入教学。
2. **分步重试**：某个步骤失败（例如被砍中）时不清空进度，只重复该步提示。
3. **软性引导**：把左上角面板换成跟随 3D 世界坐标的指示箭头，减少 HUD 遮挡。
4. **首个商店引导**：第一层商店前追加一次「E 交互 → 三选一」的简短引导，复用本关的步骤机结构。
5. **埋点**：`_show_step()` 是天然的埋点位置，可上报每一步的耗时，定位卡住新手的环节。
