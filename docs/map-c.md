# C 地图生成适配

第一层地图现已采用 `map_c_layout.gd` 的连续几何生长算法，替代原来的 8×8 固定建筑网格和 handoff 的 Kruskal 图布局。算法先在矩形地图中生成一条主干道，再从主干道两侧生成支道，随后沿道路边和已有建筑边继续放置建筑，直到随机阶段和收尾扫描都找不到合法位置。

## 当前参数

| 参数 | 当前值 | 说明 |
| --- | ---: | --- |
| 地图范围 | 100×100 米 | 连续二维坐标，映射到 Godot XZ 平面 |
| 建筑短边 | 6 米 | 每个模型俯视水平包围盒的短边统一缩放到 6 米 |
| 建筑长边 | 按模型比例 | `long = 6 × raw_long / raw_short`，不固定为 10 米 |
| 主干道宽度 | 10 米 | 道路中心线两侧扩展 |
| 支道数量 | 主路两侧各 3 条 | 支道宽度为 4 米，方向和长度按种子扰动 |
| 道路退距 | 1 米 | 建筑与道路并集的最短距离 |
| 最小楼间距 | 2 米 | 旋转后建筑多边形之间的最短距离 |
| 最小依附重合 | 2 米 | 建筑沿依附边的投影重合长度 |
| 随机失败上限 | 连续 2200 次 | 达到后转入沿边扫描 |
| 扫描步长 | 0.5 米 | 收尾阶段沿两种长短方向扫描 |
| 外围浅水带 | 18 米 | 沿用当前水域、上岸坡道和深水逻辑 |
| 街道遭遇 | 8 个候选点 | 沿生成的清晰道路段分布，沿用现有战斗系统 |

地图不固定建筑数量。实际栋数由模型尺寸、道路形状、楼间距和连续几何生长的停止条件共同决定。

## GLB 尺寸归一化

模型尺寸取 Godot 导入后、包含节点变换的水平包围盒。对每个模型计算：

```gdscript
var raw_short := minf(bounds.size.x, bounds.size.z)
var raw_long := maxf(bounds.size.x, bounds.size.z)
var uniform_scale := 6.0 / maxf(raw_short, 0.001)
var long_side := raw_long * uniform_scale
```

模型保持全轴等比缩放；模型高度不再被旧的 14×10 米地块或统一目标高度二次限制。模型、简化碰撞、遮挡检测和交互范围共同使用该缩放与建筑在地图中的旋转。

| 模型 | 归一化俯视尺寸（长×短，米） | 归一化高度（米） |

| `居民楼(1).glb` | 6.669×6 | 8.509 |

## 随机和复现

同一个 seed 会复现道路、建筑顺序、模型选择、服务分配和遭遇位置。Godot 的随机数和几何计算与 Python 参考实现不同，因此不会承诺 seed `419` 与 Markdown 中的 NumPy 参考图逐点一致；目标是生成遵守相同规则的 C 类地图。

入口候选点取建筑依附边的中点，当前只是几何候选，不保证自动成为门的朝向，也不保证已有导航系统一定能从道路走到该点。建筑碰撞、遮挡虚化、E 交互、外围水域和现有遭遇逻辑继续由第一层场景负责。

完整的原始算法说明保存在 [`map-c-generation-logic.md`](map-c-generation-logic.md)。
