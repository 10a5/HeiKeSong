## 1. 新增自适应 Boss 运行时

### 新增文件

| 文件 | 作用 |
| --- | --- |
| `adaptive_boss_runtime.gd` | 连接玩家、Boss、行为画像、观察器、策略适配器和异步模型请求；管理接入、脱离、重置与请求取消。 |
| `gameplay_observer.gd` | 聚合最近 60 秒有效游戏时间内的移动、空中状态、距离、跳跃与攻击结果。 |
| `llm_bridge.gd` | 通过异步 HTTP 调用 Ollama 或 OpenAI-compatible 服务，校验配置、请求上下文和模型返回值。 |
| `strategy_adapter.gd` | 根据行为画像生成确定性的本地策略，在没有有效模型策略或请求失败时提供回退。 |
| `tests/test_llm_bridge.gd` | 使用本机模拟 HTTP 服务验证请求、响应校验、超时及取消等行为。 |

以上五个脚本各新增一个同名 `.gd.uid` 文件，共计 10 个未跟踪文件。

### 数据流与调度

```text
玩家已发生的动作、公开状态和本地攻击结果
    ↓
boss_brain 的行为画像 + gameplay_observer 的近期统计
    ↓
adaptive_boss_runtime 构造有限上下文
    ↓
本地策略适配器 / 异步 LLM 策略请求
    ↓
校验后的 directive → boss_brain.apply_llm_directive()
    ↓
本地反应 FSM → mirror_boss 执行动作
```

- 默认每 **0.25 秒**检查本地策略，每 **12 秒**尝试请求一次 LLM。
- 至少观察到 **4 次成功出牌**，并且相较上一次请求有新增成功出牌证据，才发送模型请求。
- 网络请求异步执行，同一桥接器只允许一个在途请求；暂停游戏时停止新的策略调度，在途 HTTP 请求仍可能完成。
- 有效 LLM 策略被接受后，本地适配器停止覆盖它；请求失败时恢复本地规则，并允许后续周期重试。
- 玩家或 Boss 死亡时停止调度；脱离 Boss 或重置本局时取消在途请求并清理对应状态。
- 模型负责选择有限策略，实时移动、命中、伤害、抽牌和胜负仍由游戏代码结算。

### 行为观察内容

观察器默认每 0.2 秒聚合一次样本，维护最近 60 秒的移动、静止和空中时间，累计水平／垂直／总移动距离、平均速度、与 Boss 的距离分布，以及跳跃成功／拒绝、攻击命中／落空／伤害等公开结果。窗口边缘按有效时间裁切，尚未结束的采样周期也计入摘要。

运行时还加入 Boss 当前生命、能量、护盾、状态、入场保护时间、偏好距离和已有连招信息。它使用调用方构造的有限上下文，不将手牌、牌堆、未来随机数或密钥作为模型输入。

## 3. 行为画像与反应规划修正

`boss_brain.gd` 的主要变化：

- 初始策略改为 `observe_and_probe`，默认翻滚响应改为 `disengage`；重置观察时同步恢复默认策略和翻滚反制阈值。
- 学到“翻滚接攻击”后，具体采用何种反应由当前策略授权，不再仅凭证据直接固定为闪避。
- 玩家死亡时返回观察状态；公开状态快照新增 `slash_time_left`。
- 置信度和翻滚接攻击比例使用近期权重，使旧习惯随时间衰减；同时保留原始计数供解释和统计使用。
- 数值策略只接受有限数值，策略名称禁止换行；反应枚举继续受白名单约束。
- 合并冷却窗口内的重复反应，只有反应发生变化时才发出对应信号。
- 保留调用方显式设置的暂停处理模式，支持实验场与正式游戏各自的暂停需求。

## 4. 玩家攻击结果反馈

`player.gd` 新增公共信号：

```gdscript
signal attack_observed(kind: String, hit: bool, damage: float)
```

近战命中、突进沿途命中、射击结算和下落攻击命中会向观察器提供反馈；伤害值取目标实际生命减少量。突进移动段与后续出拳窗口共享观察标记，避免同一张突进卡在这两个阶段重复上报。角色重置和动作清理会复位标记。

`mirror_boss.gd` 移除自身重复声明的同名信号，改为继承玩家基类的反馈接口。

**统计边界**：当前近战主要上报命中，射击会显式上报命中或落空；观察器不会把所有“没有收到命中反馈”的攻击自动计为落空。因此这部分数据还不能当作完整的全技能命中率。

## 5. LLM 配置与响应约束

### 配置来源

1. 优先读取 `user://llm_config.json`。
2. 其次读取 `res://llm_config.local.json`。
3. 没有上述 JSON 配置时，检查 `user://evomap.key` 或项目根目录 `key.txt`，使用内置 EvoMap 默认配置。

内置默认模型标识为 `evomap-gemini-3.1-pro-preview`。自定义配置支持 `ollama` 和 `openai_compatible` 两种 provider；凭据通过 `api_key_env` 或 `key_file` 在请求时读取，不接受在配置中直接填写 `api_key` 字段。

`.gitignore` 新增忽略项：

```gitignore
key.txt
llm_config.local.json
```

本次汇总未读取或复制任何密钥内容。

### 请求和返回限制

- 远程 endpoint 使用 HTTPS；HTTP 仅允许本机回环地址，不跟随重定向。
- 默认请求超时 20 秒，上下文上限 64 KiB，默认响应体上限 64 KiB。
- 返回内容必须是仅含 `summary` 和 `directive` 的 JSON；拒绝 Markdown 代码块、额外字段、非法枚举、非有限数值及越界参数。
- 允许的策略字段为 `name`、`roll_response`、`slash_response`、`dash_response`、`aggression`、`exploration_rate` 和 `roll_attack_threshold`。
- `aggression` 范围为 0–1，`exploration_rate` 为 0–0.35，`roll_attack_threshold` 为 0.1–0.95。
- 自定义兼容服务可控制是否发送 `response_format`；内置 EvoMap 配置省略该可选字段。

配置通过校验只代表配置可被使用，不代表远程服务、凭据或模型已经完成实连验证。这里的“世界模型”指统计行为画像与状态摘要，不包含在线训练。
